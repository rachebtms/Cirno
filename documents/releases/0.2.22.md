# Cirno 0.2.22

## Independent automation input identities

Fix scheduled jobs failing with `Input event ID was reused with different
content` before reaching their target Agent. A saved job could retain the
coordination message envelope of the input that created it. Later invocations
then presented new content under that already consumed message identity.

Cron jobs and local triggers now share filtering of the creating input's
coordination envelope, work-report payload and hidden-history marker. The
normalizer runs both when saving new tasks and when dispatching existing tasks.
Destination conversations and channel routing remain intact. Each invocation
keeps its own automation identity; existing input receipts and duplicate-message
protection are preserved.

Existing tasks do not need to be recreated or have their reminder text changed.
Previous failures remain in history and are not automatically replayed. Inspect
the destination conversation before choosing to run a missed task manually.

## Upgrade and validation

Python packages, the Web UI, configuration examples and current documentation
use 0.2.22. Startup adds the 0.2.21 → 0.2.22 configuration-version migration
without resetting instance data. Preserve the existing instance volume and Setup
selectors when upgrading to `ghcr.io/rachebtms/cirno:0.2.22`.

Focused regressions exercise the real automation admission path with consumed
coordination receipts, two successive invocations, legacy task metadata,
preserved channel routing and duplicate suppression. Full backend and frontend
tests, Chromium/WebKit checks, wheel installation, AMD64/ARM64 image builds,
`+presets.rachebtms --verify`, recreation persistence and `+all --verify` run in
GitHub Actions before publishing the multi-platform image.
