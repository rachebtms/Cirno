# Cirno 0.2.12

## Context consolidation can continue when learning fails

Consolidation saves a usable task checkpoint independently of optional experience, profile and Skill updates. Invalid learning output, source-validation errors and learning-file failures no longer prevent checkpoint persistence or task continuation. Ordinary findings automatically reference the immutable archived batch; the model no longer has to reproduce exact quotations. Profile and Skill edits use supplied source handles while retaining scope, revision and user-authorization checks.

Conversation notices and Memory show completed learning updates, incomplete updates, the error and the retained source. Partial writes are identified as incomplete until acknowledged. Original messages and generated plans remain available for recovery. These notices survive browser refreshes and have readable fallbacks for other channels.

`/consolidate retry [source-id]` recovers one retained batch in its original conversation and Project scope. It first replays saved writes without a model request. If the saved output is invalid or absent and no effects have been acknowledged, explicit recovery can regenerate learning only. It preserves the existing task checkpoint, archive position and checkpoint journal. File or revision conflicts remain visible rather than triggering blind regeneration.

## Stable instruction prefixes and explicit retry controls

Replacement checkpoints now appear in history after the system/developer instructions. Repeated compactions retain the captured instruction prefix during the same run, including when learning updates profiles or Skills. Consolidation appends its instructions and bounded references to the accepted transcript. The replaced history necessarily changes its cache match; actual cache hits and billing remain provider-dependent.

Settings → Context consolidation adds **Consolidation generation retries** (`max_retries`, JSON alias `maxRetries`), default 1, range 0–10. This counts additional sequential generation attempts; 0 allows only the initial attempt. Provider-level network retries are separate. A learning failure does not automatically regenerate a usable checkpoint. Generation, saving and explicit recovery introduce no additional concurrent model requests; cancellation is not retried.

## Upgrade

Use `ghcr.io/rachebtms/cirno:0.2.12` with the existing instance and Homebrew mounts. The 0.2.11 → 0.2.12 migration updates `lastRunVersion`, retaining configuration, conversations, checkpoints, memory, profiles, Skills and credentials. Older supported versions follow the existing migration chain. Failed learning batches from earlier versions remain available for explicit recovery; historical failure notices remain part of the conversation record.
