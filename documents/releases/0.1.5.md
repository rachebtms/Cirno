# Cirno 0.1.5

## Long-running work

Model configurations can select plaintext reasoning-history replay. Automatic respects the endpoint's known behavior; DeepSeek tool requests require preservation. Effective input estimation accounts for ignored history, while returned reasoning stays in the saved transcript. Reasoning-only responses survive length recovery, empty-answer retries and finalization.

Compaction has an independent output budget and reasoning-effort setting. A configurable reminder asks the execution model to save a task checkpoint before reaching the active input budget. Working-state handoffs retain the task, verified results, hypotheses, next action and artifact references. Invalid or unavailable summaries fall back to bounded source evidence, including reasoning and attempted tool arguments, with an explicit evidence-checkpoint label in the Web UI. Complete source records remain archived. Regular conversation progress is visible outside folded execution activity; Cirno keeps its internal process folded and delivers progress through its message tool.

See [Model context and long-running work](../model-context.md).

## Memory and context

External OpenAI-compatible embedding APIs join the existing optional local CPU worker. Both use bounded incremental chunks, disk-backed vectors and the same BM25/hybrid retrieval pipeline used by the agent and settings. Endpoint/model/chunk size/dimensions distinguish indexes. API keys are masked, can be rotated or cleared, and remain part of the instance backup. BM25 remains the default; API failure is visible and falls back to lexical retrieval.

Active compaction uses a configurable percentage of the selected model's context window, while reserving output space. Live context estimates grow during reasoning, text generation and tool output, then calibrate to reported usage. Changed MEMORY.md snapshots are appended to fresh input rather than rewriting the system prefix; historical assistant text is replayed without cosmetic rewriting.

## Supervision, tools and persistence

Cirno can inspect and change another idle conversation's workspace, PTC mode and model configuration, then continue it. Running workers must first be stopped. Configuration preserves history, Goal, Project and access permissions, and updates all connected browser clients.

Built-in tool activity has concise summaries and expandable arguments, multiline commands, results and errors. Node operations require approval in AI-approval mode; Default rejects remote operations and Full Access executes them directly. Reviews bind the exact remote configuration and operation. Uninspected remote scripts go to the owner rather than using similarly named local files as evidence.

CLI Apps inherit the same non-secret persistent directory settings as shell tools. Full-image Python installs use the persistent user environment. Additional SSH, Git credential, AWS, Cargo and local user-data paths persist inside the instance volume. Bundled service dependencies remain separate from user packages.

## Complete backup and restore

Settings → Backup & restore exports the complete instance, with optional extra paths. Existing workspaces and common CLI configuration, credential and package directories are suggested automatically. SQLite backup includes committed WAL data. Transfers use the existing Web UI port and disk streaming, including resumable downloads. Export requires an idle runtime. Import validates and previews the archive; restore applies before runtime startup, with instance rollback on copy failure. External folders are merged and require compatible software paths and platforms. Backups contain credentials and are not encrypted.

See [Backup and restore](../backups.md) for scope and restore behavior.

## Upgrade

Replace the image with `ghcr.io/rachebtms/cirno:0.1.5` or `ghcr.io/rachebtms/cirno:0.1.5-full`, retaining the existing instance volume, mounts, environment and reverse-proxy network. Instances using the 0.1.3/0.1.4 directory layout do not need re-registration. Stop active work before recreating the container. Files installed only in the old container's writable layer remain outside that persistence guarantee. Refresh the browser or installed Web app after upgrading.
