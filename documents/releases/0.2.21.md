# Cirno 0.2.21

## Shared local and remote command duration

Local `shell.exec`, Agent `nodes.execute` and the Nodes command dialog share
the default command runtime in Settings → Shell execution. The existing
`tools.exec.max_runtime` defaults to 3600 seconds; `max_runtime_limit` defaults
to 86400 seconds and bounds explicit single-call requests. Agent commands accept
`max_runtime`, or its mutually exclusive `timeout` alias. Runtime validation and
model-facing parameter definitions share one implementation.

A default runtime of 0 removes the deadline for calls without an explicit
duration. Setting the requested-duration ceiling to 0 also permits an explicit
0 for unlimited execution. Restart Cirno after changing the shared settings.
Router small-task budgets remain separate. Local silence detection, sandbox
settings, SSH connection deadlines and detached remote jobs retain their own
scope and lifecycle.

The Nodes command dialog no longer imposes a separate 130-second browser
deadline. It waits for the server result. A direct Node command is not replayed
after a browser disconnect: its outcome is reported as unconfirmed because it
may still be running or already completed. This prevents a delayed reconnect
from resubmitting a command after the mutation receipt cache expires. Use
`nodes.start` and its durable job ID for long tasks that need reconnectable
status and output. Confirmed remote exit codes and partial output remain intact;
an unconfirmed SSH outcome is never automatically retried.

## Resume without discarding accepted work

Router `goals.control(resume)` and `conversations.control(continue)` preserve
running work, child agents, Shell sessions and queued messages. Unfinished Goals
are reactivated in place. When execution or accepted input already owns the next
turn, the controls return `continuation_queued: false` instead of cancelling it
and submitting another turn.

This includes the gap between a session message's durable acceptance and its
arrival in the Worker queue. FIFO ordering and delivery receipts are retained.
Repeated or concurrent resume controls share session admission, and delayed
duplicate message delivery cannot execute an already acknowledged input again.
Idle conversations admit one saved-context continuation; interrupted-turn
recovery retains its existing recovery identity and completed-tool checkpoint.
Explicit Stop and replacement controls retain their cancellation semantics.

## Upgrade and validation

Python packages, Web UI manifests, configuration examples and current documents
use 0.2.21. Startup adds the 0.2.20 → 0.2.21 configuration-version migration
without replacing instance data. Keep the existing instance volume and Setup
selectors when upgrading to `ghcr.io/rachebtms/cirno:0.2.21`.

Focused regressions cover shared runtime bounds, unlimited SSH deadlines,
native tool parameters, instance-scoped configuration, approval, FIFO recovery,
receipt deduplication and browser reconnect behavior. Full tests, browser checks,
wheel installation and AMD64/ARM64 image validation run in GitHub Actions.
Image gates include minimal startup, `+presets.rachebtms --verify`, recreation
persistence and `+all --verify` before publishing the multi-platform manifest.

After installing CA certificates, the container uses HTTPS for its official
Ubuntu archive, security and ports repositories. CI uses the same transport
for runner dependencies. Repository signatures and normal APT installation are
unchanged; no third-party mirror or package download workaround is introduced.

WebSocket integration assertions wait for observed inbound delivery rather than
a fixed 100 ms sleep, retaining an explicit bound under slow CI scheduling.
