# Cirno 0.2.4

## Router and Worker execution

Router and Worker contracts have separate prompts, personality files and tool catalogs. The Router coordinates medium and large work through durable Workers before substantive execution. Paper analysis, research, development, debugging, experiments, long jobs and tasks of uncertain size belong to Workers. Goal execution and continuation retain these boundaries.

A direct Router task must have an immediately known completion path within nine ordinary tool calls and ten cumulative seconds of tool execution. The runtime shares this allowance across model rounds, native calls and nested PTC calls. Replies and coordination remain available after exhaustion. The Router cannot launch transient private subagents to bypass durable Workers. Workers retain execution tools without the Router's small-task budget and exclude Router-only supervision, Project management and visible-message delivery.

Unavailable or exhausted work is rejected before asking for approval. Timeout errors identify the unfinished work and possible completed effects so a Worker can inspect state before retrying. Task classification follows the role prompt; permissions and execution budgets are enforced in code.

## Editable system prompts and caching

Settings → Personality provides three automatically saved additions: Shared, Router and Worker. Each supports up to 32,000 characters and can be cleared. The shared default contains the owner's unlimited-token effort instruction; role-specific additions start empty. These additions do not change provider billing, context/output limits or Harness permissions.

Saved additions apply to the next turn without restarting. A running turn keeps its captured values through subsequent requests and compaction. Worker subagents receive shared and Worker additions. Internal maintenance has a separate contract and treats personality profiles as reference data.

Stable identity, framework and role instructions precede mutable profiles and Project context. Tool declarations retain deterministic ordering. Dynamic memory and task-state snapshots extend fresh input without rewriting previous messages. Archived summaries are labelled as historical evidence rather than authorization. Cache usage continues to use provider-reported metrics.

## Memory correctness and long context

- Reads, search, tags, statistics and semantic retrieval share the same user/Project/conversation visibility rules. Moving a conversation out of a Project no longer retains memory access through its originating-session metadata.
- Task checkpoints use separate conversation/Project slots. Switching back restores that Project's checkpoint; visible legacy checkpoint IDs remain readable and writable. Automatic compaction does not overwrite explicit checkpoints.
- Immutable body hashes are checked on current and historical reads, semantic indexing/snippet extraction and Dream batch preparation. Corrupt batch input is reported without claiming or consuming the batch.
- Source reads enforce a total 16,000-character page budget, including memory pointers and long individual lines. Source indexing also reads bounded fragments, preserving line numbers and overlap without loading a full JSONL message line.
- `WORKER.md` is indexed with the other profiles. Same-Project findings from different Workers can be revised or linked while retaining their original provenance and visibility scope.

## SSH job inspection

Remote job status and stop checks read the full process command line. Linux process-list width limits cannot truncate the job identity at the end of long command arguments and misreport an active job as unknown or stopped.

Inspection checks the exit receipt after probing the process. A job that finishes during that probe is reported as completed or failed rather than unknown.

## Upgrade

Startup migrates 0.2.3 configuration to 0.2.4 while preserving conversations, profiles, credentials and settings. Instances on 0.1.6 and earlier supported 0.2.x versions follow the existing migration chain.
