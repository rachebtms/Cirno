# Cirno 0.2.8

## One image, command-selected tools

Docker now publishes one image for AMD64 and ARM64. The base includes Cirno, Python/uv, Node/npm/npx, Git and SSH. Optional research, document, browser and operations tools install at startup through the independent `cirno-setup` package.

The image entrypoint runs `cirno-setup --serve`. It verifies dependencies before starting Cirno, stops on installation errors and hands the server container signals directly. Package installation is serial and does not make LLM requests.

Select components in Compose rather than application settings:

```yaml
services:
  cirno:
    image: ghcr.io/rachebtms/cirno:0.2.8
    command: ["+presets.rachebtms", "--timeout", "1800", "--verify"]
```

Omit `command` for the minimal environment, or choose individual components such as `+pip.pytest`, `+npm.mcporter`, `+channels.telegram` or `+system.libreoffice`. Installer options precede `--`; optional Cirno server arguments follow it. Component selections and timeout are never saved to `config.json`.

`+rachebtms` is shorthand for `+presets.rachebtms`. Setup verifies newly installed components immediately; `--verify` adds a final serial check of every selected dependency after the whole installation. A failed check reports its component and prevents Cirno from starting.

The research preset replaces the former full image, including document/scientific Python libraries and pytest, Office, scientific LaTeX, browser automation, PDF/OCR/FFmpeg, server utilities and approved CLI tools. Telegram and local embedding dependencies remain optional; installing them does not enable the features or supply account credentials. Historical `-full` tags remain historical releases and are no longer published.

## Standard installations and persistence

Python environments and framework dependency installation use uv. Agent packages install into a standard persistent virtual environment, separate from Cirno's service dependencies. Agent pip remains available for existing Skills. npm uses its normal global prefix, and Playwright retains its official driver, Chromium and Headless Shell. No Python path injection, command dispatcher, executable stripping or browser-driver replacement is required.

Tool packages, caches and CLI configuration reuse the existing `~/.cirno` root. The Compose examples bind its Homebrew subdirectory to the normal Linuxbrew prefix. Missing selected APT dependencies and user-added system packages are restored after container replacement, reusing cached archives. Office and LaTeX install only when selected. Initial installation and uncached restoration need network access; custom APT repositories and arbitrary system-file edits still require deployment configuration or a derived image.

## Upgrade

Preserve the existing instance root and external workspace mounts. Replace `compose.full.yaml` with `compose.rachebtms.yaml`, or set the research preset directly in your Compose service. Use the same Compose files when pulling and recreating the container. Allow time for the first selected tool installation and inspect container logs for progress.

The 0.2.7 → 0.2.8 migration updates `lastRunVersion` while retaining configuration, conversations, profiles, memory and credentials. The existing migration chain continues to support 0.1.6 and earlier 0.2.x versions. See [Docker deployment](../docker.md), [environment setup](../setup.md) and [instance upgrades](../migrations.md).
