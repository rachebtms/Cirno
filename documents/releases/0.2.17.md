# Cirno 0.2.17

## Model responses and tool execution

Chat Completions streams keep tool arguments separate when a gateway reuses a wire index with different call IDs. Ambiguous fragments fail with a classified, retryable protocol error instead of mixing arguments from unrelated calls. Requests select one completion candidate consistently, so alternative answers cannot introduce additional tool executions. A completed answer is retained if only the trailing usage or stream-close step fails.

Provider failures retain content-free diagnostic metadata, distinguish malformed responses from connection failures, and avoid selecting the same provider/model as its own fallback. Recovery actions, Goal state and execution reports now agree on resumed and failed work.

Public tool operations validate their own required fields, accepted arguments and limits. Tool errors remain explicit through native and programmatic calling. MCP reconnects replay operations only when their declared read-only or idempotent contract permits it; an uncertain mutation is not silently executed again. File image reads share the selected model's visual-capability checks. CLI installation deadlines, search configuration refresh failures and SSH fingerprint-check cancellation are handled at their owning layers.

## Context, memory and learning

Task checkpoints remain independent of optional experience extraction. Invalid learning output can receive bounded, sequential correction attempts with field-level feedback; failed learning retains its original source and retry state. Input reviews accept the supplied source IDs, and validation messages omit input contents and external help URLs. Optional learning instructions cannot prevent a checkpoint that otherwise fits the model context from being saved.

Archived transcript identities include their Project scope. Moving a conversation between Projects, or between a Project and private scope, no longer reuses an archive with the previous visibility rules. Previously archived evidence remains readable under its original scope.

The configurable memory-injection limit now reaches 32,768 tokens. Fixed Skill injection is controlled by **Always inject** inside each installed Skill's details, with automatic saving and existing availability rules preserved.

## Conversation display

Consecutive Router execution and heartbeat activity between visible messages share one Working / Worked disclosure. Expanded activity retains each original heartbeat, reasoning step and tool result; accumulated execution duration excludes idle gaps. Incoming messages, delivered replies and consolidation reports keep their own boundaries. Live heartbeat inputs retain their system origin instead of appearing as owner messages.

Deferred activity details retain failures across partial loading and newly arriving references. Failed items wait for an explicit retry, pending requests are not duplicated, and stale requests from a previously opened conversation view cannot replace the current view's state.

## Setup, verification and upgrade

Setup initialization and ownership preparation respect the same configured subprocess deadline as installation and verification, including `--timeout 0` for no limit. The unified image, persistent instance volume and command-selected optional dependencies remain unchanged.

The source-audit regression run passed 8,994 backend tests, 3,139 frontend tests and 23 browser cases. Browser coverage includes Chromium and WebKit keyboard visibility, memory-cloud interactions, pane-size changes, settings editing and Router activity. Backend and frontend suites retain 23 and 1 intentional skips respectively; clean-environment wheel installation and container provisioning are checked separately by GitHub Actions.

Use `ghcr.io/rachebtms/cirno:0.2.17` with the existing instance volume and Setup selectors. Startup advances `lastRunVersion` from 0.2.16 through the offline migration chain; this step changes only the configuration version. Python packages, Web UI, example configuration and current documentation use 0.2.17.
