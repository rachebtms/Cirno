# Cirno 0.1.1

## Browser setup

New instances register their owner and configure their first model in the Web UI. Passwords require at least 10 characters, an uppercase letter and a punctuation or symbol character. Existing configurations and authentication settings are preserved. Browser sessions survive service restarts and can be revoked by signing out.

## Fixes

- Cirno no longer receives the conversation-title tool or instructions to rename itself. Ordinary conversations retain automatic titles, and manually chosen titles are stored in session metadata as well as the sidebar.
- Title changes and Goal operations reject requests from replaced conversations. Goal updates also check that another operation has not changed the Goal while the request was in flight.
- Deleting a conversation during a Goal scheduler tick no longer prevents other Goals from being checked.
- Interrupted SSH job submissions and invalid PID responses retain an explicit unknown outcome instead of remaining stuck in the submitting state.
- Concurrent browser file saves serialize their revision check and write, so one browser cannot silently overwrite another browser's accepted edit.
- Inbox pagination ignores responses belonging to a category that has since been left and preserves newer records received during pagination.
- Session-list and history errors retain the server's reason rather than reducing every failure to an HTTP status.
- Source checkouts serve the shared frontend build directory, including during browser setup.

## Conversation and inbox behavior

Cirno has a clear-conversation button with confirmation. It uses the existing session reset operation, stops the active execution, clears the transcript and removes its old Goal and report state. Saved memories and other conversations remain available. Empty conversations use the same composer presentation as the new-conversation page.

The inbox records explicit work reports, failed runs, pending actions and system events. Ordinary replies and successful turn completions stay in their conversations. Existing ordinary-message notifications are removed on the first inbox access after this update; reports and failures are retained.

## Personal Telegram and settings

- Restrict Telegram to personal private chats. Add owner-verified, rotating two-minute PIN binding, disconnection and independent Cirno/Actions/Reports/System delivery switches. Inbox notifications reuse the durable delivery outbox and can link to their authenticated Web UI action.
- Route Telegram and Heartbeat through Cirno while keeping ordinary automations attached to their selected conversation.
- Persist delegated instructions as user input with the originating conversation identified.
- Stream execution activity for Goal continuations, fix deferred activity requests after navigating away and back, and add independent brief/detailed reasoning and tool-step display preferences.
- Organize settings into smaller named pages with grouped desktop and mobile navigation.

## Review and verification scope

The review covered the first-party source inventory across the agent, tool registry, PTC, session storage, coordination, Goals, memory, notifications, Nodes, channels, configuration, CLI Apps, Skills, SDK, gateway, Web UI and deployment files. Generated assets, installed dependencies and archived upstream references were excluded from source review.

Regression cases exercise fixed Cirno naming, title and Goal races, session replacement, interrupted SSH submissions, simultaneous browser saves, inbox pagination, notification migration and the clear-conversation control. Desktop and mobile visual checks compare the empty Cirno composer with the new-conversation composer and inspect the clear dialog and inbox. GitHub Actions runs frontend and backend checks before building the container, testing browser registration under a 400 MB container limit and publishing AMD64/ARM64 images.
