# Cirno 0.1.6

## Conversation controls

Message actions and local timestamps stay visible below messages on desktop and mobile. Copy, edit and branch controls no longer require opening a menu. Completed execution activity keeps a direct **Worked…** disclosure above the answer, including activity separated by file changes.

Editing replaces the original message bubble with a multiline editor and Cancel / Save and send controls. Attachments remain attached. Enter adds a line, Ctrl/Cmd+Enter sends, and Escape cancels. A failed save retains the draft and displays the error. Navigating to another conversation closes the editor; a delayed save response cannot reset that conversation's history. Editing or branching past tool activity warns that earlier file changes and external actions are not undone, including when tool history is text-only or loaded on demand.

## Delegated work and Goal reports

Delegated conversations report terminal results and model/API failures to their coordinator without depending on the model to call the reporting tool. Retry health is reported while a request is waiting and after it recovers. Routine waiting and progress remain conversation state rather than repeated coordinator messages; undelivered retry notices coalesce without discarding task results.

An Inbox write failure no longer turns successful execution into a failed task. Notification delivery retries independently without rerunning the worker or repeating its external actions. One conversation's report failure no longer stops other Goals from waking. Long Goal recaps use an explicitly marked report excerpt while retaining the complete recap. When a delivery queue is full, old reports drain before the new result is retried; an old report cannot mark a different Goal's report as delivered.

## Backup recovery and browser sessions

Backup import rejects files or symbolic links that replace the instance/state ancestors or the restore workspace. Staged layouts are validated again before replacement. Restores with a different configuration filename remain retryable, and cancelling one preview preserves another import's scheduled restore.

Rollback retains every original file until recovery completes, including original SQLite sidecars. A second interruption during recovery or cleanup can be retried without deleting files already recovered.

Signing out revokes that browser session's API tokens and unused connection tokens, closes its live sockets and invalidates attachment and backup-download capabilities. Other signed-in devices remain connected.

## Upgrade

After the images are published, use `ghcr.io/rachebtms/cirno:0.1.6` or `ghcr.io/rachebtms/cirno:0.1.6-full`. Keep the existing instance volume, external workspace mounts, environment and reverse-proxy configuration. Instances on 0.1.3–0.1.5 use the same storage layout and do not need re-registration or data migration. Stop active work before recreating the container, then refresh the browser or installed Web app. See [Docker deployment](../docker.md#upgrading-from-016).
