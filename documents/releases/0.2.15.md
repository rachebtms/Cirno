# Cirno 0.2.15

## Recoverable memory revision conflicts

An existing task checkpoint requires `expected_revision` from the latest read or successful write. Missing versions now report `memory_revision_required`; stale versions report `memory_revision_conflict`. The rejected write explicitly returns `write_applied: false`, together with the authorized current record's ID, revision, source and content. Previously the generic rejection text did not identify the current record or distinguish these cases, making unchanged retries hard to recover from.

The Agent can compare the returned current content with its proposed checkpoint, preserve relevant progress/evidence, and retry with the returned revision. This also covers stale event/knowledge updates and historical grouped tool calls. Another intervening edit is still rejected. No automatic overwrite, duplicate memory, extra model request or concurrent recovery is introduced. Visibility checks run before exposing any conflict snapshot.

`memory.update` continues to require `memory_id` and `expected_revision` in its native tool schema. A missing required parameter fails before invoking the writer. The first checkpoint can still be created without a version.

## Clear persistence outcomes

Tool descriptions and shared instructions explain when a version is needed and how to reconcile conflicts. The Agent must receive a non-error write result with the saved ID and revision before claiming that a memory or checkpoint was saved. A conflict's `current` snapshot is the existing record, not a saved copy of the rejected proposal.

Native execution retains the error outcome. PTC also raises a nested `ToolError`; a script that catches it may finish successfully while that nested write remains failed. Regression coverage checks both caught and uncaught PTC failures, rejected writes, current snapshots, preserved history, concurrent edits and cross-conversation privacy. Recovery snapshots are ordinary tool results and do not rewrite the system prefix.

## Upgrade

Use `ghcr.io/rachebtms/cirno:0.2.15` with the existing mounts and Setup selectors. Frontend, backend packages, example configuration and documentation use the same version. Startup updates `lastRunVersion` from 0.2.14 without changing conversations, memory, credentials, Skills or owner preferences. The existing supported migration chain remains available.
