# Cirno 0.2.19

## Long-context checkpoint recovery

Automatic continuation and replay can intentionally omit a fresh control input from persisted history. Pre-request context consolidation now maps the accepted-history boundary separately from the new-message append cursor. This fixes `ValueError: Checkpoint summary does not belong to the persisted transcript`, which could repeatedly stop an already consolidated conversation before any tool executed, including after Continue or a model-preset change.

Invalid summary boundaries are checked before changing runtime-checkpoint metadata or appending transcript rows. Existing history, summaries and the stable instruction prefix are retained. Regression coverage includes 6,100 archived messages, persisted and omitted inputs, duplicate checkpoint delivery, restart restoration and immediate consolidation on the next continuation. The fix does not require clearing conversation history, add model concurrency or change prompt assembly.

Runtime retry and failure reports inherit a human-action question only from the same execution turn. Questions from older turns remain in their original reports and delivery records instead of appearing as the current failure's blocker. Explicit Agent reports retain their omit-to-keep and empty-to-clear behavior.

## Background execution and Working state

Worker reports that independently wake the Router use the complete visible execution lifecycle, including terminal and idle notifications when the Router remains quiet. Automatic Goal slices retain the admitted display turn ID and registered owner until execution actually completes. Independent inputs continue to acquire separate owners.

These changes prevent completed background work from leaving an orphaned Working state in the browser or restoring it on refresh. Server-side regression tests exercise real transcript persistence and reconnect projection with subscribers both present and absent. Stopping a Goal does not prematurely hide a model request that is still running.

## Router execution budget

Settings → Goals & execution now exposes the cumulative Router tool time budget (1–3600 seconds), with a default of 60 seconds instead of 10. After restart, the Router prompt and native/PTC admission use the same configured value. Model and approval waiting are excluded; the nine-call limit and medium/large-task delegation remain in place. Remaining time does not modify the stable prompt prefix.

## Settings navigation

Saved settings that need a restart no longer trigger a confirmation dialog on every workbench tab switch. The tab activation guard, route navigation, closing Settings and browser Back/Forward retain pending-write checks without prompting to restart. Settings continues to show the pending-restart notice and manual Restart action. A failed save still preserves its draft and error rather than silently discarding the edit.

## Upgrade and verification

The root distribution, workspace Python packages, Web UI manifests, example configuration and current documentation use 0.2.19. Startup adds the 0.2.18 → 0.2.19 configuration-version migration while retaining instance data and previous migration steps.

Upgrade with `ghcr.io/rachebtms/cirno:0.2.19`, keeping the existing instance volume and Setup selectors. After deployment, an interrupted long conversation can be resumed from its saved state; repeated Continue attempts on the old affected release are unnecessary.

GitHub Actions performs the complete backend and frontend checks, Chromium/WebKit browser regressions, clean wheel installation and AMD64/ARM64 container validation. Image validation covers minimal startup, `+presets.rachebtms --verify`, recreation persistence and `+all --verify` before multi-platform publication. Heavy release checks run remotely.
