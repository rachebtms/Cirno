# Cirno 0.2.3

## Router input and recovery

Durable system inputs, including first-use awakening, are deduplicated while a
turn is running and after restart. A completed introduction left in an older
release's follow-up journal is retired when `BOOTSTRAP.md` is empty. Conversation
history, SOUL and USER profiles remain intact.

System messages injected during a running turn reach the next model request.
Anthropic and Responses transports preserve the base instructions when adding
awakening, heartbeat or Worker report inputs instead of replacing them.

System-origin messages retain their runtime context, including event provenance,
receipt time and relevant task or memory context, while keeping their system role.

## Context accounting

When a new request extends the last measured request, its input budget adds the
estimated new messages to the provider's reported input usage. A low local token
estimate no longer hides appended assistant output or tool results. Rewritten
requests and fallback-provider usage keep their existing independent accounting.

Responses server compaction now shares the percentage-based output headroom used
by normal requests and Codex compaction. Setting the output ceiling as large as
the context window no longer reduces its native compaction threshold to one
token. The configured headroom percentage and safety margin apply to each path.

## Inbox

Marking individual or all notices read updates older pages already loaded in the
Inbox. A poll started before that write cannot restore stale unread rows or
counts. Refresh reloads the selected category, including records outside the
shared latest-page snapshot, and responses from replaced connections are ignored.

## SSH credentials and settings

- SSH working directories supplied inside the credential's SSH fields are saved
  on creation and update. Partial edits preserve the existing directory; Node
  enrollment can still explicitly replace it.
- Node enrollment waits for the currently selected credential's startup settings.
  Late responses from another selection or a closed editor cannot enable saving
  with stale settings.
- Model capability checks keep the connection fields fixed and block form
  submission until the test finishes.
- Reconnecting a server-created Terminal uses the same canonical ID instead of
  opening another shell.
- Remote job journals perform storage I/O off the gateway event loop and settle
  accepted writes before cancellation returns. A failed initial journal write
  prevents SSH submission. Job status verifies the process identity as well as
  its PID, so PID reuse cannot keep an old job marked as running.

## Runtime concurrency and delivery

Profile synchronization is serialized across callers, preventing simultaneous
SOUL/USER imports from conflicting over the same memory revision.

Credentials, Node services and durable delivery storage initialize and access
SQLite off the gateway event loop. Recording an accepted outbound message and
placing it in the delivery queue settle together before cancellation returns.
An interrupted send retains an unknown result instead of being blindly replayed;
an interrupted claim before transmission remains pending for recovery.

The scheduler prevents concurrent executions of the same automation. Run now
immediately reports a pending task and rejects a duplicate request, while
different automations can still run concurrently. Cancelled or completed runs
release their execution slot.

Fallback model clients close even when continuation checks reject the candidate
before a request is sent, or preparing its continuation raises an error.

## Upgrade

Startup migrates 0.2.2 configuration to 0.2.3, preserving conversations, profiles,
credentials and settings. Older supported instances follow the existing migration
chain. See [instance upgrades](../migrations.md).
