# Cirno 0.2.11

## SSH execution and job recovery

Node commands return stdout, stderr and the remote exit code, including nonzero command results. A complete remote execution receipt confirms completion even if the SSH connection later closes. Missing receipts are reported as an unknown execution outcome; commands that may have run are never automatically submitted again. SSH keepalives and bounded connection attempts improve tunnel reliability. Read-only job status queries can reconnect once within their existing deadline.

Node jobs are monitored by the server even when Settings is closed. Settings → SSH Nodes exposes the status-check interval and completed-record retention period; zero disables polling or retains records indefinitely, respectively. Checks retain the last known state and report connection failures. Active and unconfirmed jobs are not expired. Terminal states cannot be overwritten by late acknowledgements or stale checks, and deleted records are not resurrected.

## Context and grounded learning

Consolidation can locate a unique verbatim archive quote without requiring the model to count messages. Text blocks preserve their newlines during evidence validation. Ambiguous, rewritten or invented quotes remain errors. Retrying consolidation after a citation validation failure can generate a corrected result, including failures saved by earlier versions. Interrupted storage writes continue to reuse the original generated plan, and completed learning is not applied twice. Original evidence remains available after failure; these changes add no concurrent model requests.

Recent request usage details survive browser refreshes during an active turn. Workers receive clearer milestone-update instructions, and completed prose is delivered when a provider returns tool calls without streaming its accompanying text. DuckDuckGo searches retry transient failures once within the original deadline and preserve diagnostic information without exposing configured secrets.

## Memory and setup controls

The Memory tab adds sequential Load all and a saved, configurable cloud display limit. Pagination retains the submitted filters; interrupted loading preserves completed pages and can resume. Larger selections avoid SQLite parameter limits.

`cirno-setup --timeout 0` disables installation and verification deadlines across apt, pip, npm, Homebrew, downloads, embedding assets and browser checks. The default remains 1,800 seconds. Optional dependencies are selected through the existing container command arguments; no additional persistent root or Settings installation list is introduced.

## Upgrade

Use `ghcr.io/rachebtms/cirno:0.2.11` and preserve the existing instance mounts. The 0.2.10 → 0.2.11 migration updates `lastRunVersion` while retaining conversations, configuration, profiles, memory and credentials. Earlier supported versions follow the existing migration chain. Node monitoring settings use the existing instance store, and the cloud limit uses owner preferences.
