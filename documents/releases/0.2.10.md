# Cirno 0.2.10

## Reliable automatic settings saves

Switching settings categories, closing Settings or selecting another workbench tab now waits for pending runtime settings writes, including edits made before the autosave delay expires. Edits made during an existing request are saved afterward. A failed save keeps the draft and error visible instead of leaving the page. Shared proxy edits use the same save queue.

Responses from an unmounted Settings page or an earlier server connection no longer overwrite current settings. The restart decision after a save uses the newly acknowledged configuration. Provider connection and advanced request controls are disabled together while their submitted configuration is being saved.

## Complete settings controls and restart tracking

Memory library once again exposes the shared-memory context budget and index scan batch. Tools & CLI Apps includes the CLI Apps master switch, allowing disabled CLI Apps to be re-enabled. Idle consolidation trigger and retention percentages accept fractional values.

Restart tracking compares internal fingerprints of actual configuration values. Rotating a masked embedding API key now requests a restart without exposing its value in the browser payload or restart baseline. Live additional system-prompt edits no longer prevent a reverted runtime setting from clearing the pending-restart status.

## Upgrade

Use `ghcr.io/rachebtms/cirno:0.2.10` and retain the existing instance mounts. The 0.2.9 → 0.2.10 migration updates `lastRunVersion` while preserving configuration, conversations, profiles, memory and credentials. Earlier supported releases continue through the existing migration chain. The unified image and optional setup selectors remain unchanged; dependency installation and verification run in Actions for both AMD64 and ARM64. See [Docker deployment](../docker.md), [setup selectors](../setup.md) and [migration details](../migrations.md).
