# Cirno 0.2.5

## Mobile input and model controls

The application root now follows the visible viewport when the mobile keyboard opens. Critical styles in the shipping HTML previously overrode the dynamic viewport height, leaving login, registration and chat inputs behind the keyboard. Focus and draft contents are retained when the keyboard opens or closes.

Browser regression checks load the shipping entry HTML and simulate keyboard viewport changes in Chromium and WebKit, covering login, registration (including password confirmation) and chat. These checks do not replace testing with a physical iPhone keyboard.

Custom-provider fallback icons in the model selector now stay centered with their text at mobile and desktop widths.

## Automatic settings saving

Runtime settings no longer briefly show Save/Cancel actions while edits are pending or being saved automatically. This applies to the shared configuration component, including workspace paths, proxy settings and idle compaction. Fields that wait for editing to finish still save when focus leaves their group; Enter also submits single-line fields.

A failed save retains the draft, reports the error and offers Retry/Cancel. Successful responses continue to preserve newer edits made while a request is in flight.

## Full-image Python libraries

The full image preinstalls `python-docx`, `openpyxl`, `python-pptx`, `pypdf`, `pdfplumber`, `reportlab`, `lxml` and `debugpy` for Agent Python commands. Image-provided libraries are exposed to the persistent user Python environment at startup, including existing instance volumes. User-installed packages retain precedence, and Cirno's service environment remains separate.

Container smoke checks verify these imports before and after container recreation, alongside the existing user-package persistence checks. See [Docker deployment](../docker.md#full-image).

## Upgrade

Startup migrates 0.2.4 configuration to 0.2.5 without changing conversations, profiles, credentials or settings. Older supported instances follow the existing migration chain. Keep the instance volume and workspace mounts when replacing the container. See [instance upgrades](../migrations.md).
