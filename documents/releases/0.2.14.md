# Cirno 0.2.14

## Fixed Skills and memory files

Settings → Skills now selects installed Skills for full automatic injection in Router and Worker conversations, including transient Worker subagents. Disabled Skills and unmet dependencies remain excluded. Author-declared automatic Skills stay included and are identified in the selector. Missing selections remain removable.

Settings → Memory library selects additional UTF-8 files under Agent Home's `memory/` directory, with a separate combined excerpt budget. MEMORY.md keeps its existing budget. Selections save automatically and apply to the next input without restarting. Changed memory is appended as a fresh snapshot; existing history and system prefixes are preserved. Removing a selection also produces a fresh snapshot. Missing/unreadable files and paths escaping the memory directory report errors.

## Router tools and reply recovery

Router runtime inspection and working-state checkpoints remain usable after the small-task execution budget is exhausted. Ordinary investigation still uses that per-turn budget, while coordination remains available. Policy denials now explain the execution decision instead of presenting it as a tool implementation error. Native and PTC calls share the same policy.

Malformed reply arguments explicitly report that no message was sent. Recovery asks for complete JSON and short ordered messages while retaining previously delivered messages. A response truncated by the output limit never executes its incomplete tool-call batch; tool-based replies and ordinary Worker text receive distinct continuation guidance. Stream chunks reusing one tool index for conflicting call IDs fail explicitly instead of combining arguments. Excessively nested JSON arguments produce a recoverable tool error.

Tool names use `group.operation` in explanations and PTC declarations, while native model APIs use `group__operation`; these identify the same tool. Native calls retain their required wire spelling.

## Credentials

Revealing a saved Token, password or SSH password now displays its value immediately. A reusable eye button switches between visible and masked text. Hiding the value makes no additional read request, and revealing/toggling does not mark the record as edited or save it. Leaving the page conceals the value and clears an unmodified revealed record. Credential guidance distinguishes metadata-only lists from the explicit read tool for Agent-visible records.

## Setup verification

Dependency verification checks every incoming version constraint even when the same package appears through multiple extra/dependency paths. The recursion guard still terminates cycles without skipping conflicting constraints.

## Upgrade

Use `ghcr.io/rachebtms/cirno:0.2.14` with existing mounts and Setup selectors. Startup updates the configuration version from 0.2.13 without replacing conversations, memory, Skills, credentials or owner settings. New fixed-context selections start empty; existing author-declared automatic Skills retain their behavior.
