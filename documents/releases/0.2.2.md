# Cirno 0.2.2

## Context budgeting

The maximum output setting now acts as a ceiling instead of reserving its full
value before every request. Context compaction reserves a configurable percentage
of the window (5% by default), and each request limits output to the space left
after its measured input and safety margin. Large output settings therefore keep
the input window usable. Normal requests, fallback models and checkpoint generation
share this policy. See [model context](../model-context.md).

## SSH startup and command duration

SSH credentials and enrolled Nodes share a remote working directory, initialization
script and environment variables. New Terminals, direct commands and persistent
jobs use the same startup sequence; inspecting or stopping a job does not rerun it.
Remote execution requires Bash and OpenSSH; persistent jobs also require `setsid`.

The maximum requested command duration accepts zero to remove the ceiling.
An explicit zero duration then means no time limit. A positive maximum retains
its existing bounded-request behavior.

## Visual inputs

Agents can use `files.view_image` to add an actual image to model context, using
the existing file reader's permissions, conversion and size limits. Model setup
checks image and native video understanding with small visual samples. Owners
can rerun checks or explicitly select each capability in model settings.
Authentication errors, timeouts and inconclusive answers stay unverified.
Native video checks require the OpenAI-compatible `video_url` transport.

## Router and settings fixes

- The Router header can pause and resume its heartbeat. Pause persists across
  restarts and discards queued heartbeat inputs before they reach the model.
  An already-running turn can finish; owner messages and worker reports continue.
- First-use awakening acknowledges its durable delivery receipt, preventing a
  completed introduction from replaying after restart. System-origin inputs
  retain their role through persistence and request preparation.
- Autosaving settings show their save status without briefly displaying manual
  Save/Cancel buttons. Failed saves retain their retry controls.

## Mobile keyboard

Login, registration and chat follow the visible viewport when the on-screen
keyboard opens or closes. Entry forms scroll within that height, focused fields
retain space above the keyboard, and touch text controls avoid focus-triggered
zoom while preserving manual pinch zoom.

## Upgrade

Use `ghcr.io/rachebtms/cirno:0.2.2` or `ghcr.io/rachebtms/cirno:0.2.2-full`,
preserving the existing instance volume and external workspace mounts. Startup
migrates 0.2.1 configuration to 0.2.2 and retains conversations, profiles,
credentials and settings. Instances on 0.2.0 and 0.1.6 run the registered migration
steps in sequence. See [instance upgrades](../migrations.md) and
[Docker deployment](../docker.md).
