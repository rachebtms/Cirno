# Cirno 0.2.20

## Execution, persistence and recovery

Accepted writes and cleanup keep their owner until settlement, including repeated
cancellation. Shared boundaries now cover conversation turns, checkpoints,
automation changes, notifications, credentials and provider/tool resources.
Commit acknowledgements remain distinct from pre-commit cancellation: a saved
change is not reported as cancelled merely because later feedback was interrupted.
Shutdown retains in-flight recovery data, and replacing a conversation prevents
older callbacks from changing its replacement.

Goal controls validate wait deadlines before stopping work and preserve saved
progress when it is omitted. Status notifications use the committed conversation
generation and current saved Goal. Automatic continuation retains earlier
answer-persistence failures for the same execution so recovery can repair them.
These changes do not add model concurrency or change the stable prompt prefix.

## Tools, providers and Setup

Provider stream failures retain their error classification for bounded recovery.
Anthropic replay preserves opaque thinking blocks, and disabling tool selection
retains the catalog and instruction prefix. Model request filtering and fallback
estimates retain each model's reasoning-history policy. Resource teardown,
explicit proxy selection and credential error reporting use shared ownership
rules without exposing secret values.
Windows CLI subprocesses omit the Linux-only desktop runtime directory while
retaining the existing environment allowlist.

MCP OAuth separates SDK/browser flows from durable credential storage while
preserving public imports, per-instance and URL isolation, deletion fences and
refresh leases. Invalid saved credential fields are ignored independently rather
than erasing valid neighboring fields. CLI, Node, file and asynchronous-action
paths retain their validation, generation and cancellation checks.

Setup verifies requested Python dependency closures, extras and version bounds;
metadata parsing is isolated from package output. npm readiness checks validate
package metadata before reuse. Linux command timeout and interruption terminate
and drain the process group; `--timeout 0` continues to mean no deadline.

## Browser and settings

View-scoped reads, writes and local state share activation ownership. Results
from retired accounts, conversations, editors and workspaces cannot overwrite
their replacements. Settings workflows share admission and revision gates while
preserving domain-specific authorization, polling and restart behavior.
Preset creation reports a failed call-order update in every supported language,
while retaining the successfully created preset for an explicit retry.

System settings separate feature runtime actions, restart receipts and channel
form persistence. Channel defaults, draft checks and saves share field assignment;
draft coercion and authoritative save validation remain distinct.

The browser client separates message acceptance, typed notifications and pure
run observation. Socket generation, transcript ordering and run ownership remain
coordinated by the client. Shell commands are not replayed, attachment delivery
retains its originating connection and expired text is removed from the queue.

Inbox notice bodies now render Markdown through the conversation renderer,
including headings, lists, tables, links and code blocks. Approval arguments keep
their literal JSON display. Existing notices use the new rendering on load.

## Upgrade and verification

Python distributions, the Web UI manifests, example configuration and current
documentation use 0.2.20. The 0.2.19 → 0.2.20 migration updates the configuration
version while retaining instance data and previous migration steps.

Upgrade with `ghcr.io/rachebtms/cirno:0.2.20`, retaining the instance volume and
existing Setup selectors. The unified image keeps optional dependencies selected
through Setup, including `+presets.rachebtms` and `+all` for exhaustive checks.

Focused local regressions cover the refactored boundaries and notification
rendering. GitHub Actions runs full frontend/backend checks, Chromium and WebKit
browser flows, AMD64/ARM64 image validation, selected/all Setup verification and
container recreation before publishing the multi-platform image.
CI preparation shares package-repository DNS setup and replaces slow regional
Ubuntu EC2 mirrors with the Ubuntu archive for runner dependencies.
The browser job allows 45 minutes for checks and environment preparation,
including slow package downloads; browser assertion timeouts remain explicit.
Frontend/browser and backend checks run as independent jobs. A separate wheel
installation job consumes the verified Web UI bundle; image builds require all
three jobs. Backend tests have a 120-second diagnostic limit with thread dumps;
twenty failures stop that run early, while a passing run executes the full suite.

Task shutdown drains children whose parent was deleted or replaced without
recreating revoked task sessions. Dispatch cleanup retains an input already
written to the durable journal while clearing its transient Working owner.
