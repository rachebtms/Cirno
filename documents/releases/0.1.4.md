# Cirno 0.1.4

## Upgrade from 0.1.3

Keep the existing instance volume and replace the image with `ghcr.io/rachebtms/cirno:0.1.4` or `ghcr.io/rachebtms/cirno:0.1.4-full`. Configuration, accounts, conversations, memory and task files retain the 0.1.3 storage layout; re-registration is not required. Back up the instance with the service stopped before recreating the container. Files installed only in the old container layer are not part of that backup. See the [Docker upgrade steps](../docker.md#upgrading-from-013).

## Mobile and conversation interface

- The top-right refresh button works in desktop browsers and installed mobile Web apps, including iPhone Home Screen apps.
- Returning from the background checks the WebSocket connection and reloads missed reasoning, tool activity and completed responses. A dead connection reconnects without resending the user's prompt.
- The context-usage control appears during the first model call. Until measurement is available, it shows an unmeasured ring rather than a fabricated zero percentage.
- Saved conversations keep their working directory visible as a locked selector. Transient workspace refresh failures retain the last valid directory data.
- Creation-only `/ptc` and `/temporary` commands are hidden from established conversations' command menus.
- The About wordmark is centered, and browser notification titles use “Cirno”.

## Settings and MCP

Settings → Goals & execution exposes the default workspace. It affects new conversations after applying the requested restart; it does not move existing files or change saved conversation directories.

Settings → AI approvals provides an independent review model, a review timeout and an enable switch. Disabling AI review leaves blocked operations for owner approval. Uncertain decisions and unavailable review models also go to the owner.

Custom MCP connections can be edited, JSON editors support formatting, and Add MCP server appears above the catalog. Authenticated remote browsers can install optional dependencies and manage Skills without a localhost-only installation restriction.

## Full container image

The optional `-full` image includes Telegram dependencies, development and media tools, Homebrew integrations and matching INT8 embedding weights. Embedding inference remains disabled by default. Slim and full images support AMD64 and ARM64 through native GitHub runners.

The instance volume retains CLI configuration and user tool installations. Full-image Python packages use a persistent user virtual environment, separate from Cirno's own dependencies. Gitea and GitHub login configuration also stays in the instance volume. Container smoke tests check tools, bundled CPU embedding inference and persistence after recreation. See [Docker deployment](../docker.md#full-image) for the tool list and storage paths.

Source distributions, dependency pins, the browser package and backend version reporting use 0.1.4.
