# Cirno 0.2.16

## Conversation commands

The WebUI command menu now scrolls through every applicable command instead of dropping entries after the first eight. Menu-loading failures display their error and an explicit Retry action. Registered control commands remain sendable before a model is configured; actual Goal requests still require model setup.

Command routing, lifecycle admission and highlighting agree on case-insensitive names, Telegram bot suffixes, aliases, tabs and multiline arguments. Invalid arguments receive a control reply rather than entering the model or becoming guidance for an active turn. Model display names retain their internal spaces. `/status` uses the same context reserve and compaction threshold budget as execution, rather than subtracting the full configured output ceiling.

The complete v0.1.6 command inventory has been checked. `/compact` and `/dream` remain compatibility aliases of the shared `/consolidate` operation, including learning-retry arguments. The legacy Git memory-history and restore commands are visible again and clearly distinguish their saved legacy versions from current catalog revisions. Extra restore arguments are rejected, replies retain transport correlation, and restart/legacy restoration require a direct human request. Retired `/pairing` and `/dream-prompt` inputs explain their replacements without calling the model or recreating unused configuration. Telegram menus and handlers use the shared command catalog.

See the [complete command comparison](../commands.md).

## Memory cloud

The cloud's expand icon opens a large view on desktop and mobile. Fit-to-view is a separate, labeled operation. Close or Escape returns to the results list and restores focus. Expanded and embedded views share rendering and node/tag interactions, use already loaded data and dispose the previous renderer when switching.

## Worker supervision and report delivery

Supervision lists include idle Workers with unfinished active, waiting, paused, blocked or stopped Goals, including their `wake_at`. Ordinary completed/idle history remains available through conversation search.

Within one model run, the full active-Goal continuation reminder is emitted initially and when Goal state changes. Unchanged follow-ups use a short reminder. Existing accepted history and prompt prefixes are not rewritten, and no additional model concurrency is introduced.

Runtime updates for one turn share an execution ID. Newer state retires obsolete, undelivered waiting/retry notices, while actual result/failure reports and already delivered history remain intact. Legacy pending receipts keep their original payload shape so upgrade recovery does not conflict with prior delivery hashes.

## Validation and upgrade

Regression coverage includes every registered/legacy command spelling, interleaved parallel Chinese tool arguments, missing-model control input, restored command discovery, waiting Workers, Goal continuation state and report/receipt compatibility. Browser checks cover command-menu keyboard/scroll access and memory-cloud expansion on narrow and desktop layouts. The parallel-argument report was not reproduced by these cases; malformed provider arguments are not heuristically rewritten.

Use `ghcr.io/rachebtms/cirno:0.2.16` with the existing instance volume and Setup selectors. Startup advances `lastRunVersion` from 0.2.15 through the existing offline migration mechanism; this patch step changes only the configuration version. Frontend, Python packages, example configuration and current documentation use 0.2.16. The unified image and command-selected optional dependencies remain unchanged.
