# Cirno 0.2.13

## Reliable learning recovery

Ordinary findings use their immutable archive batch as provenance even when the model includes old-style archive quotations. Rephrased, ambiguous or incorrectly numbered archive quotes no longer block these batch-based findings. Specific pending-memory references still require valid source revisions and visibility, and profile/Skill edits retain their source and authorization checks. Mixed archive/input references cannot be discarded to promote private evidence into shared memory.

Previously failed quote-only batches can be saved through Memory or `/consolidate retry [source-id]` without another model request. Recovery first replays the retained save plan, including after an upgrade. When regeneration is necessary, it remains sequential and preserves the existing task checkpoint and archive position.

## Detailed consolidation retry reports

`/consolidate` now advertises its supported arguments, fixing highlighting for `/consolidate retry …` in both the composer and message history. Retry results use the same collapsible consolidation report as manual checkpointing, rather than an ordinary Agent answer.

Reports show newly completed and previously completed items, memory/document/input-review counts, confirmed saved items, remaining updates and their original source. They distinguish replay from regeneration and record whether an LLM invocation was attempted. Original proposals are listed separately from saved updates. Empty extraction explicitly reports no updates, and a missing failed batch is reported as no pending work. Failure, cancellation and argument errors stay within the report lifecycle.

Reports are localized and survive browser refreshes. Desktop/mobile and light/dark browser checks cover completed, partial, empty and missing-batch results.

## Upgrade

Use `ghcr.io/rachebtms/cirno:0.2.13` with the existing instance and Homebrew mounts. Startup migrates `lastRunVersion` from 0.2.12 while retaining conversations, memory, profiles, Skills, credentials and settings. Older supported releases follow the existing migration chain. Historical failure notices remain historical records; a subsequent retry reports the current save result.
