# Cirno 0.1.2

## Settings Overview

Overview keeps model and web-search status and adds eight shortcuts: Memory library, Context compaction, Goals & execution, Personality, Telegram, Nodes, MCP and Tools & CLI Apps. Each has an icon and a short description. The layout uses two columns on desktop and one on mobile, with translations for every supported interface language.

## Fresh-deployment baseline

Cirno is an unstable release. Version 0.1.2 targets fresh deployments; it does not automatically convert older configuration keys, JSONL conversations, historical Web UI transcripts or previous memory databases. Existing files are not deleted or rewritten by an importer. Use a new Home when deploying this version from an older installation; keep the old Home separately if its contents are needed.

Removed compatibility paths include old proxy/API-selector and execution-timeout keys, the model-preset conversion interface, JSONL session and transcript importers, memory Markdown/monolithic-database importers, previous Goal metadata, deprecated module imports, CLI App Skill aliases, implicit subagent runtimes and untyped WebSocket messages. Internal tools and settings use the current contracts directly.

Telegram requires the current Web UI PIN binding flow. A previous allowlist cannot bypass owner verification. Current transport adaptations, cancellation, authorization, file revision checks and durable queue recovery remain part of the supported runtime.

## Deployment

Register the owner and configure a model in the browser. For a source checkout, follow [Configuration](../configuration.md). For containers, follow [Docker deployment](../docker.md) and select image tag `0.1.2` after the release workflow publishes it. Home remains the persistent data boundary; optional embeddings stay disabled by default. The Compose example uses a published image, one exposed Web UI port and one Home volume, with no CPU or memory limits.
