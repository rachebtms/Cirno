# Cirno 0.2.18

## Execution, restart and Goals

Completed model segments and individual tool results are saved at durable recovery boundaries during a running turn. The transcript suffix, context-summary boundary and runtime checkpoint share the existing persistence transaction. Restart recovery retains completed work and identifies unfinished tool calls without automatically repeating uncertain side effects. Goal scheduling respects pending input and recovery state before starting another continuation.

Goal resume and conversation continue share admission rules. Paused, stopped, waiting and blocked Goals can resume explicitly; completed and cancelled Goals remain terminal. Repeated requests distinguish already queued, resuming and genuinely running work. Workers can pause or stop their own Goal during automatic continuations; expanding or resuming work still requires the applicable user authorization. Routine retry and recovery health reports remain inspectable without repeatedly waking the Router or filling the inbox.

Stopping an execution settles accepted queued inputs and obsolete Goal continuations. Automatic handoffs sharing one visible turn produce one completion, while independent queued inputs retain separate lifecycles. Passive cross-conversation messages no longer start a phantom Working state. A stopped Goal does not hide a genuinely running request.

## Repeated-output protection

Settings → Goals & execution adds repeated-output protection for Router and Worker runs. It defaults to four adjacent equal prose blocks, up to two sequential corrections, and editable guidance. Owners can disable it or change its thresholds and guidance. The detector excludes fenced code, handles Chinese and Latin sentence boundaries, and retains recent output across automatic continuations while resetting for genuine user input.

On detection, the current stream closes before a correction request begins. Guidance is appended after the existing prompt history; no additional concurrency is introduced. Exhausting the correction limit pauses execution and its active Goal, preserves its recap and clears scheduled wake-up. This is reported as an output interruption rather than a provider connection failure.

## Conversation and workspace display

Returning from another browser tab reconciles replies by their persisted event identities. Replayed receipts and pending stream batches cannot create duplicate replies; distinct messages containing equal text remain visible. This applies to desktop and mobile clients.

Completed Chat Completions responses wait at most five seconds for optional trailing usage data, also bounded by the configured stream idle timeout. Empty trailers cannot prolong that grace period. Normal model thinking keeps its existing timeout settings.

The top tab strip maps mouse-wheel movement to horizontal scrolling, retains trackpad distances and inertia, and confines touch panning to its horizontal axis. Browser zoom gestures remain available, and split panes scroll independently. Selecting an already visible tab does not move the strip.

Python packages, frontend manifests, example configuration and current documentation use 0.2.18. The startup migration adds the 0.2.17 → 0.2.18 version step without resetting instance data. Keep the existing volume and Setup selectors when upgrading to `ghcr.io/rachebtms/cirno:0.2.18`.
